## 1. Objective

Before changing anything, record a **baseline** of the gateway server: which kernel and drivers it runs, how much memory it has, how it boots, and which mode it boots into. A baseline is the reference point for every later change and for troubleshooting ("what did it look like before?").

## 3. Procedure and results

### 3.1 Kernel, drivers and memory

```bash
uname -r
cat /proc/version
lsmod | head
free -h
sysctl net.ipv4.ip_forward
```

| Check | Result | Interpretation |
|---|---|---|
| Kernel version | `5.15.0-198-generic` | Ubuntu 22.04 GA kernel; noted for patch tracking |
| Build info | gcc 11.4.0, binutils 2.38 | Standard Ubuntu build |
| Loaded modules | `vmw_vsock_*`, `vmw_balloon`, `vsock`, `intel_rapl_*` | VMware guest drivers are loaded; the OS is aware it runs as a VM (`vmw_balloon` lets the hypervisor reclaim memory) |
| Memory | 1.9 GiB total, 299 MiB used, 1.4 GiB available; swap 1.3 GiB, 0 used | Sufficient headroom for a gateway |
| IP forwarding | `net.ipv4.ip_forward = 0` | **gw01 does not route packets yet.** Enabling this in Phase 1 turns it into a router |

### 3.2 Boot process

```bash
systemd-analyze
systemd-analyze blame >> boot-gw01.txt
journalctl -b | head -15 >> journal-gw01.txt
ls /boot
```

| Check | Result |
|---|---|
| Total boot time | 38.117 s = 17.022 s kernel + 21.095 s userspace |
| Default target reached | `graphical.target` after 19.809 s in userspace |
| `/boot` contents | `vmlinuz-5.15.0-198-generic` (kernel), `initrd.img-5.15.0-198-generic` (initial RAM disk), `vmlinuz.old` / `initrd.img.old` (previous kernel kept as fallback), `grub/` (bootloader), `config-*` and `System.map-*` (build configuration and kernel symbol map) |

**Boot chain:** firmware (BIOS/UEFI) → GRUB bootloader → Linux kernel → initramfs → systemd (PID 1) → services → login.

The per-service boot times (`systemd-analyze blame`) and the first journal lines of this boot were saved on gw01 as `boot-gw01.txt` and `journal-gw01.txt`; they are added to `evidence/day-01/` with the next update.

### 3.3 Boot target

```bash
systemctl get-default
sudo systemctl set-default multi-user.target
systemctl get-default
```

| Before | After |
|---|---|
| `graphical.target` | `multi-user.target` |

systemd created the symlink `/etc/systemd/system/default.target → /lib/systemd/system/multi-user.target`.

**Reason:** a server does not need a desktop environment. `multi-user.target` provides networking and all services without a GUI, which reduces boot time, memory use and attack surface.

| Legacy runlevel | systemd target |
|---|---|
| 0 | poweroff.target |
| 1 | rescue.target |
| 3 | multi-user.target |
| 5 | graphical.target |
| 6 | reboot.target |

## 4. Issues encountered

| # | Symptom | Cause | Resolution |
|---|---|---|---|
| 1 | `systemctl get default` → `Unknown command verb get.` | Typo: the verb is `get-default` (one word with a hyphen) | Re-ran as `systemctl get-default` |
| 2 | Uncertainty whether `>> tee file` saves output | `>>` redirects to a *file*, `\|` pipes to a *program*; `>> tee` would create a file named `tee` | Use `command \| tee file` (screen + file) or `command >> file` (append to file only) |

## 5. Lessons learned

- A baseline captured *before* changes makes later troubleshooting faster and provable.
- `ip_forward` is the single kernel setting that decides whether a Linux host routes traffic.
- Servers should boot into `multi-user.target`; the previous kernel in `/boot` is the fallback if an update fails.
- Command output saved to files is evidence for documentation and audits.
